# Decomposition Principles

## 1. Granularity Rules
- **Atomicity**: Each subtask does ONE thing (research, analyze, format, synthesize)
- **Reusability**: Subtasks should produce artifacts reusable by multiple downstream tasks
- **Clarity**: Task description must be actionable without ambiguity

## 2. Dependency Rules
- **DAG Structure**: No circular dependencies allowed
- **Parallelization**: Maximize independent tasks to reduce total execution time
- **Data Flow**: Explicitly declare what each task needs (input) and produces (output)
- **ID Convention**: Tasks are numbered sequentially starting from 0

## 3. Tool Assignment Rules
- **Minimal Assignment**: Only assign tools when the task CANNOT be completed without them
- **No Redundancy**: Do not assign generic tools (like LLM reasoning) - assume all tasks have access to base reasoning
- **MCP Special Protocol**: If using `UseMCPPlugin`, the sequence ListServers → ListTools → CallTool MUST be in a SINGLE subtask

# Artifact Management

| Field | Description | Example |
|-------|-------------|---------|
| `required_artifacts` | Data/objects needed before execution | `["search_results", "user_preferences"]` |
| `output_artifacts` | Data/objects produced for downstream use | `["filtered_data", "analysis_report"]` |

**First task**: `required_artifacts` is always `[]` (only depends on original user request)
**Final task**: Must consume all relevant `output_artifacts` to produce user-facing response

## For Content Formatting
- Links: Use [text](https://url)` format. Never wrap in code blocks
- Images: Use ![alt](https://url) format. Never wrap in code blocks
- Code: Only use code blocks for actual code snippets, not for links/images
- Tone: Use emojis and conversational style in final output if user tone is casual

## For Tool-Specific Protocols
### WebSearchPlugin
- Use for facts requiring verification, current events, or external knowledge

### UseMCPPlugin (CRITICAL)
- Never split the three steps across subtasks

- Violation: Creating separate subtasks for each step

- Inject relevant context into required_artifacts as chat_context
