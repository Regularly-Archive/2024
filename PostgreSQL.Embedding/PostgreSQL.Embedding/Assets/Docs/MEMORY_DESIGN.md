# 记忆系统设计方案

## 层级结构

```
user -> app -> sessions -> runs
```

- **user**：用户根目录
- **app**：应用级记忆（soul）
- **sessions**：会话级记忆，按日期组织
- **runs**：任务级记忆，单次执行

---

## 三层记忆架构（冷-温-热）

参考人脑认知模式，记忆分为三种状态：

```
┌─────────────────────────────────────────────────────┐
│                    热记忆（Active）                   │
│                 memory/index.md                      │
│                                                     │
│    精简索引，Agent 启动时直接加载                     │
│    上限 150-200 行，超过就降级                       │
│    每条记忆带元数据和溯源链接                        │
└─────────────────────────────────────────────────────┘
    │ 被引用时激活
    ▼
┌─────────────────────────────────────────────────────┐
│                    温记忆（Dormant）                 │
│              memory/dormant/{id}.md                 │
│                                                     │
│    近期不活跃但重要的记忆                            │
│    需要主动查询才会加载                              │
│    被引用时回到热记忆                                │
└─────────────────────────────────────────────────────┘
    │ 长期无引用
    ▼
┌─────────────────────────────────────────────────────┐
│                    冷记忆（Archived）                │
│              memory/archive/{id}.md                 │
│                                                     │
│    很久没用的归档记忆                                │
│    需要主动搜索才能找到                              │
│    保留历史记录，但不参与决策                         │
└─────────────────────────────────────────────────────┘
```

### 类比人脑

| 层级 | 类比人脑 | 访问成本 |
|------|----------|----------|
| 热记忆 | 工作记忆 | 直接可用 |
| 温记忆 | 长期记忆，需要"想一想" | 需要查询 |
| 冷记忆 | 需要翻旧照片才能想起来 | 需要主动搜索 |

## 存储结构

```
memory/
├── index.md                    # 热记忆索引
├── dormant/                    # 温记忆
│   └── {memory-id}.md
├── archive/                    # 冷记忆
│   └── {memory-id}.md
├── sessions/                   # 会话摘要
│   └── {yyyy-mm-dd}-{session-id}.md
└── topics/                     # 主题索引
    └── {topic-name}.md
```

### 短期记忆（会话摘要）

路径：`/short_term/{user_id}/{yyyy-mm-dd}.md`

按用户 ID 和日期组织。

### 长期记忆

融合在热-温-冷三层架构中，不再单独区分 soul.md。

## 遗忘机制（用进废退）

### 核心原则

**遗忘不是删除，是降级。**

- 不用的记忆逐渐沉到冷区
- 用到的记忆会被激活，回到热区
- 历史不会丢失，只是"很难想起来"

### 降级规则

```
active（热） ──时间+无引用──▶ dormant（温） ──时间+无引用──▶ archived（冷）
     ▲                              │                              │
     └────────── 被引用时激活 ◀───────┴────────── 被引用时激活 ◀──────┘
```

| 重要性 | 首次降级时间 | 二次降级时间 |
|--------|--------------|--------------|
| P0 | 永不降级 | - |
| P1 | 90 天 | 不再降级 |
| P2 | 30 天 | 再过 180 天归档 |
| P3 | 7 天 | 直接归档 |

### 升级规则

当用户问到相关内容时：
1. 搜索匹配 dormant 和 archived 记忆
2. 如果找到，状态改为 active
3. 最后引用时间更新为当前日期
4. 重新进入热记忆索引

### 引用的定义

以下情况算"引用"，更新最后引用时间：
- 用户在对话中提到相关关键词
- Agent 在回复中主动引用了这条记忆
- 用户通过搜索找到了这条记忆

以下不算引用：
- 整合时的维护操作
- 主题索引的更新

---

## 重要性分级

| 等级 | 含义 | 降级规则 |
|------|------|----------|
| P0 | 核心记忆，永不遗忘 | 用户显式标记，永不降级 |
| P1 | 重要记忆，长期保留 | 90 天无引用降级 |
| P2 | 一般记忆 | 30 天无引用降级，再过 180 天归档 |
| P3 | 临时记忆 | 7 天无引用直接归档 |

### 判断方式（双轨制）

| 方式 | 说明 | 优先级 |
|------|------|--------|
| 显式标记 | 用户明确说"记住这个" | 最高，设为 P0 |
| 隐式判断 | Agent 根据内容判断 | 次之，自动分配 P1-P3 |

## 会话摘要格式

文件路径：`memory/sessions/{YYYY-MM-DD}-{session-type}-{short-id}.md`

```markdown
# 会话摘要

## 基本信息
- 会话ID: {session-id}
- 日期: {YYYY-MM-DD}
- 时长: {约 X 分钟}
- 类型: main / channel / automation
- 价值判断: high / medium / low / skip

## 主题
- 主题1
- 主题2

## 关键词
关键词1, 关键词2, 关键词3

## 重要决策
- 决策1：描述
- 决策2：描述

## 用户表达
- "用户原话1" —— 上下文说明
- "用户原话2" —— 上下文说明

## 待跟进
- [ ] 待办事项1
- [ ] 待办事项2

## 来源
- 原始会话: sessions/{session-id}（保留至 {过期日期}）
```

## 记忆条目格式

热记忆索引文件：`memory/index.md`

```markdown
# 记忆索引

## 分类名称

### 记忆标题
- 状态: active
- 重要性: P1
- 最后引用: {YYYY-MM-DD}
- 创建时间: {YYYY-MM-DD}
- 来源: memory/sessions/{session-file}.md

记忆内容的概括描述。
可以包含多个要点。

---

### 另一条记忆标题
...
```

### 元数据字段

| 字段 | 取值 | 用途 |
|------|------|------|
| 状态 | active / dormant / archived | 决定加载优先级 |
| 重要性 | P0 ~ P3 | 影响降级速度 |
| 最后引用 | 日期（YYYY-MM-DD） | 判断是否降级的依据 |
| 创建时间 | 日期（YYYY-MM-DD） | 知道记忆产生时间 |
| 来源 | 文件路径 | 指向会话摘要，可追溯细节 |

## 整合流程（Auto Dream）

### 触发条件

满足以下任一条件时触发：
- 距离上次整合超过 24 小时 + 新增 5 个以上会话
- 用户手动触发："整理记忆"、"执行整合"
- 定时任务：每天凌晨自动执行

### 六阶段流程

**阶段一：定位（Orientation）**
- 读取 `memory/index.md`，构建当前记忆地图
- 扫描 `memory/sessions/`，检查新会话摘要

**阶段二：收集信号（Gather Signal）**
- 读取新的会话摘要
- 提取关键信息：决策、用户表达、待跟进项

**阶段三：整合（Consolidation）**
- 合并重复记忆
- 解决矛盾（保留演变过程）
- 新记忆写入 index.md

**阶段四：冷热分离（Prune）**
- 检查每条记忆的"最后引用时间"
- 根据重要性和无引用时长，决定是否降级

**阶段五：修剪索引（Index）**
- 确保 index.md 在 150-200 行以内
- 按重要性和时效性重新排序

**阶段六：清理（Cleanup）**
- 检查超过保留期限的原始会话
- 删除原始对话文件，释放存储空间

## 渐进式回忆流程

```
用户提问
    │
    ▼
查询热记忆 ──找到──▶ 直接回答
    │
    │ 没找到
    ▼
查询温记忆 ──找到──▶ 回答 + 激活记忆（dormant → active）
    │
    │ 没找到
    ▼
查询冷记忆 ──找到──▶ 回答 + 激活记忆（archived → active）
    │
    │ 没找到
    ▼
回答"没有相关记忆"
```

## 被动触发提示

当用户问某话题，但忘了之前聊过相关内容时：

1. 正常回答用户问题
2. 同时检索相关记忆（包括 dormant 和 archived）
3. 如果找到相关但不活跃的记忆，主动提示

### 提示格式

```
顺便提一下，你之前还聊过 [相关主题]，还想得起吗？
```

### 注意事项

- 不要过度提示，只在真正相关时才提
- 提示内容简洁，不要打断主回答

## 记忆冲突处理

同一主题在不同时间的记忆可能矛盾：

**处理原则：不简单覆盖，保留演变过程。**

```markdown
### 某决策主题
- 状态: active
- 重要性: P1

**时间线演变**：
- {日期1}：初始想法，描述
- {日期2}：调整方向，原因
- {日期3}：最终决定，结果

**当前状态**：{当前结论}
```

## 时效性处理

### 时间敏感信息

- 计划日期（"下周三开会"）
- 版本信息（"当前使用 v1.2"）
- 状态信息（"正在处理中"）

### 过期标记

```markdown
### 某条时效性记忆
- 状态: archived（已过期）
- 重要性: P2
- 过期时间: {YYYY-MM-DD}

记忆内容。
（此信息已过期，仅作历史记录）
```

## 配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 热记忆上限 | 200 行 | 超过后触发降级 |
| 原始会话保留时长 | 30 天 | 之后删除，只保留摘要 |
| 整合触发阈值 | 24h + 5 会话 | 时间和会话数双重条件 |
| P1 降级时间 | 90 天 | 无引用后降级 |

| P3 降级时间 | 7 天 | 无引用后直接归档 |

## 设计原则总结

| 原则 | 说明 |
|------|------|
| 渐进式回忆 | 从概括到细节，层层深入 |
| 用进废退 | 频繁用的留在热区，不用的沉下去 |
| 保留历史 | 遗忘不是删除，是降级 |
| 溯源能力 | 每条记忆能追溯到原始来源 |
| 自动维护 | 整合、分级、清理自动化 |
| 用户可控 | 重要记忆用户可以标记和保护 |
